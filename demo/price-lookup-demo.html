How a price lookup works

This page tells you how the shop gets the price of a product. It also tells you what occurs when a client sends too many requests.

Based on
  • The design notes of the Price API, version 2.
  • This page does not cover how prices are calculated. The pricing team owns that part.
  • This is a demo page. The values are examples.

1. Key points

  • The client talks only to the gateway.
  • The price service reads the cache first. It reads the database only on a cache miss.
  • The gateway limits each client to 80 requests per minute.

2. Terms

This page uses each term below with one meaning only.

TermMeaningIn the code
ClientThe web shop or the mobile app that asks for a price.web, app
GatewayThe entry point for all API requests. It applies the rate limit.api-gateway
ServiceThe service that returns the price of a product.price-service
CacheA copy of each price. It lives for 5 minutes.redis
DatabaseThe store of all prices.postgres

3. Overall flow

Swipe sideways to see all of it.

The order of the calls
  1. 1The client sends the request to the gateway.
  2. 2The gateway sends the request to the service.
  3. 3aThe service reads the cache.
  4. 4The service returns the result to the gateway.
  5. 5The gateway returns the response to the client.
Only sometimes (dashed)
  1. 3bThe service reads the database only when the cache has no copy.

4. Procedures

Before you start
  • You have an admin account for the shop.
  • You know the product ID.

To clear the cached price of a product

  1. Open the admin page of the product.
  2. Click Clear cache.
  3. Make sure that the page shows "Cache cleared".

The next request reads the price from the database.

To raise the rate limit of a client

  1. Open the client in the gateway settings.
  2. Type the new limit and click Save.
Cautions
  • If you clear the cache of all products at one time, the database gets all requests for 5 minutes.

    6. The rule

    Rule
    • Below 60 requests per minute, the gateway works normally.
    • From 60 requests per minute, the gateway adds a warning header.
    • From 80 requests per minute, the gateway rejects the request with 429.

    Try it: change the requests per minute
